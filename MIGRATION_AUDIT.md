## 11. JavaScript и интерактивность

### Конфигурация

`window.SITE_CONFIG` хранит метку запуска, данные трёх тарифов, Telegram username, email, заголовок оплаты, три строки реквизитов и сообщение о доставке.

### Функции и обработчики

- `updateContactLinks()` — удаляет `@` из Telegram username, собирает сообщение о выбранном тарифе и создаёт Telegram/email URL.
- `selectPlan(key)` — выбирает тариф с fallback на `guide`, обновляет название, текущую и старую цену в диалоге, затем обновляет контакты.
- `apply()` — применяет config, строит строки оплаты и кнопки копирования, обновляет контактный mailto, выбирает `guide`, добавляет capture-обработчики выбора тарифа.
- Clipboard — `navigator.clipboard.writeText(line)` копирует реквизит; текст кнопки меняется на 1,2 секунды.
- Покупка — каждому `.js-buy` назначается открытие `buyDialog.showModal()`; отдельный capture listener сначала выбирает план.
- Закрытие покупки — кнопка `[data-close]`, клик по backdrop и нативная клавиша Escape.
- Юридические тексты — кнопки `[data-legal]` вставляют строку из `legalText` через `innerHTML` и открывают `legalDialog`.
- Закрытие legal — кнопка `[data-legal-close]`, клик по backdrop и нативная клавиша Escape.
- Reveal — `IntersectionObserver` при threshold `0.12` добавляет `.visible`; fallback в `catch` показывает элементы.
- CSS одновременно задаёт `.reveal { opacity: 1 !important; transform: none !important; }`, поэтому текущий reveal-эффект фактически отключён, хотя observer продолжает создаваться.
- FAQ работает нативно через `<details>/<summary>`, без JavaScript.
- Внутренние ссылки используют `scroll-behavior: smooth`.

### Политика конфиденциальности — шаблон

Юридические тексты являются короткими шаблонами, не полноценными финальными документами.

## 17. Media queries и breakpoint

Уникальных breakpoint два:

- `max-width: 950px` — tablet и ниже;
- `max-width: 620px` — mobile.

В CSS они повторяются: `950px` встречается в 4 media query, `620px` — в 5. Порядок каскада важен, так как более поздние блоки уточняют/перекрывают ранние.

Группы media query:

1. Базовая адаптация layout: `950px` и `620px`.
2. Тарифная сетка: `950px` и `620px`.
3. Компактный масштаб страницы: `950px` и `620px`.
4. Секция инвестиции: `950px` и `620px`.
5. Сравнение форматов: только `620px`.

## 18. Поведение по ширинам

### Desktop (`>950px`)

- Sticky header с логотипом, двумя навигационными ссылками и CTA.
- Hero, editorial, money и investment — двухколоночные.
- Четыре карточки преимуществ в ряд.
- Три тарифа в ряд; средний тариф поднят на 10 px.
- «Что внутри» фактически одноколоночное из-за `.inside-layout-clean { display:block !important; }`.
- Мобильная sticky-панель скрыта.

### Tablet (`621–950px`)

- Все ссылки внутри header nav скрываются.
- Hero, editorial, inside, money и исходный `.buy` переходят в одну колонку.
- Преимущества — две колонки.
- Тарифы — одна колонка; featured-тариф больше не поднят.
- Investment — одна колонка, карточка сравнения ограничена 650 px.
- Мобильная sticky-панель покупки показывается.

### Mobile (`≤620px`)

- Контейнер получает 12 px бокового отступа с каждой стороны.
- Текст бренда скрывается, остаётся круг `ET`.
- Основные CTA в hero и investment становятся полноширинными.
- Преимущества — одна колонка.
- Footer становится вертикальным.
- Действия диалога становятся полноширинными.
- Две карточки сравнения форматов складываются вертикально.
- Блок суммы экономии складывается вертикально; размер суммы 40 px.
- Sticky-панель покупки остаётся видимой над нижним краем.

## 19. Потенциальные проблемы доступности

- Нет skip-link для перехода к основному содержимому.
- На ширине `≤950px` скрыты все ссылки header nav, включая доступ к «Что внутри» и FAQ; остаётся только sticky CTA к тарифам.
- Глобальное `a { text-decoration:none }` убирает стандартное обозначение ссылок; не у всех текстовых ссылок есть иной устойчивый признак.
- Явные стили `:focus-visible` отсутствуют.
- Диалоги не связаны с заголовками через `aria-labelledby`; фокус после закрытия явно не восстанавливается кодом.
- Статус «Скопировано» не объявляется через `aria-live`.
- Изменение текста/цен в диалоге не объявляется assistive technology.
- Секции trust bar и quote не имеют доступного заголовка.
- У изображений есть хорошие `alt`, но нет явных `width`/`height`; CSS `aspect-ratio` частично стабилизирует layout.
- Следует отдельно проверить контраст мелкого акцентного/приглушённого текста и uppercase-подписей.
- Нативные `<details>/<summary>`, `<dialog>`, `lang="ru"` и единственный `h1` — положительные стороны текущей основы.

## 20. Потенциальные проблемы SEO

- Есть title, description, lang и один `h1`, но нет canonical URL.
- Нет Open Graph, Twitter Card, favicon и изображения для социальных превью.
- Нет структурированных данных Product/Offer/FAQPage/Organization.
- Юридические тексты добавляются только JavaScript и отсутствуют в исходном DOM.
- Контакты и данные продавца являются заглушками.
- Нет robots meta; это не ошибка само по себе, но политику индексации нужно определить при миграции.
- Нет отдельных URL для тарифов и юридических документов.
- Заголовки trust bar и quote отсутствуют; часть структуры страницы не обозначена для поисковых систем.
- Данные тарифов продублированы в HTML и JavaScript, что создаёт риск рассинхронизации цены.

## 21. Потенциальные проблемы производительности

- HTML весит 5,29 МБ, главным образом из-за Base64 PNG.
- Base64 увеличивает передаваемый текст, задерживает разбор HTML и не позволяет браузеру независимо кешировать изображения.
- Два PNG суммарно занимают 3,94 МБ после декодирования; отсутствуют WebP/AVIF, responsive variants и `srcset`.
- Второе изображение загружается сразу; `loading="lazy"` отсутствует.
- У `<img>` нет HTML-атрибутов `width`/`height` и `decoding`.
- CSS и JavaScript полностью inline; отдельное кеширование невозможно.
- Несколько последовательных CSS-блоков повторяют одни и те же селекторы и media query, увеличивая сложность каскада.
- IntersectionObserver запускается, хотя fallback-правило с `!important` уже всегда показывает `.reveal`.
- `backdrop-filter` и крупные тени могут быть дорогими на слабых мобильных устройствах.
- Положительно: отсутствуют сторонние библиотеки, трекеры, сетевые шрифты и внешние render-blocking запросы.
